Aim:
To study Linux inode structures, hard links, symbolic links, and memory-mapped file I/O.

Commands Used:

ls -i sample.txt
stat sample.txt
find . -name "sample.txt"

ln sample.txt hardlink.txt
ln -s sample.txt softlink.txt

gcc mmap_file.c -o mmap_file
./mmap_file

Observations:

1. ls -i displays the inode number.
2. stat provides detailed file and inode information.
3. find locates files in the directory tree.
4. Hard links share the same inode as the original file.
5. Symbolic links have a different inode and point to the original file.
6. mmap() maps the file directly into virtual memory for reading and writing.

Comparison:

Memory-Mapped I/O
- Faster for large files.
- Direct memory access.
- Less copying between user space and kernel.

Traditional read()/write()
- Simpler implementation.
- Suitable for small files.
- Requires explicit read/write system calls.

Conclusion:

Hard links share inode information, while symbolic links create separate inode entries. Memory-mapped I/O provides efficient file access by mapping files directly into a process's virtual address space.
